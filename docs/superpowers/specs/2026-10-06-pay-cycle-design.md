# Pay Cycle — นับรายจ่ายตามรอบเงินเดือน

วันที่: 2026-10-06
สถานะ: design (อนุมัติแล้ว 2026-10-06)

## ปัญหา

แอปนับ "เดือนนี้" ตั้งแต่วันที่ 1 ของเดือนปฏิทิน แต่เงินของ Mark เข้าปลายเดือน เงินที่เข้า 29 ก.ย. คือเงินที่ใช้ไปถึงปลาย ต.ค. ยอด "เดือนนี้" และงบจึงตัดผิดจังหวะ: ต้นเดือนดูเหมือนยังไม่ได้ใช้อะไร ทั้งที่ใช้เงินก้อนนี้มาแล้วหลายวัน

เป้าหมาย: ยอดรวม งบ และหน้ารายการ นับตาม **รอบเงินเดือน** แทนเดือนปฏิทิน

## ขอบเขต

**ทำ:**
- คำนวณวันเงินออกและรอบจากกติกา ไม่ต้องตั้งค่า
- หน้าหลัก: ยอดรอบนี้, ช่วงวันที่ของรอบ, "อีก N วันเงินออก"
- งบ: นับยอดใช้ตามรอบ + "ใช้ได้วันละ ฿X"
- หน้ารายการ: เปิดมาที่รอบนี้ + ปุ่ม "รอบก่อน" / "รอบนี้"

**ไม่ทำ (YAGNI):**
- หน้าตั้งค่าวันเงินออก — กติกาอยู่ในโค้ด (แอปใช้คนเดียว)
- บันทึกรายรับ / ยอดเงินเดือน
- แก้วันเริ่มรอบด้วยมือเป็นรายเดือน
- เปลี่ยนโครงสร้าง tab `budgets` หรือข้อมูลที่มีอยู่
- เปลี่ยนยอด "วันนี้" และกราฟ "สัปดาห์นี้"

## ข้อตกลงจากการ brainstorm

| หัวข้อ | ข้อสรุป |
|---|---|
| วันเงินออก | วันทำการสุดท้ายที่ไม่เกินวันที่ 29 — ถอยหลังข้ามเสาร์ อาทิตย์ และวันหยุดธนาคาร |
| ปฏิทินวันหยุด | วันหยุดสถาบันการเงินตามประกาศ ธปท. |
| ที่เก็บวันหยุด | ในโค้ด (`lib/holidays.ts`) ไม่ใช่ Sheet |
| รอบ | วันเงินออก ถึง วันก่อนเงินออกครั้งถัดไป |
| งบของรอบ | รอบที่เริ่มปลายเดือน M ใช้งบของเดือน M+1 (รอบ 29 ก.ย. – 28 ต.ค. = งบ `2026-10`) |
| เดือนที่ไม่มีวันที่ 29 | ใช้วันสุดท้ายของเดือน แล้วถอยตามกติกาเดิม |

ยืนยันกับของจริงแล้ว: ก.ค. 2569 วันที่ 29 เป็นวันอาสาฬหบูชา และ 28 เป็นวันเฉลิมพระชนมพรรษา กติกาให้วันจันทร์ที่ 27 ก.ค. ตรงกับวันที่เงินออกจริง

### ทำไมเก็บวันหยุดในโค้ด

- แอปต้องรู้รอบทันทีที่เปิดหน้า ถ้าวันหยุดอยู่ใน Sheet ทุกหน้าต้องรอโหลดอีกรอบก่อนจะรู้ว่ารอบเริ่มวันไหน และหน้ารายการต้องรอก่อนตั้งช่วงวันที่เริ่มต้น
- การคำนวณเป็นฟังก์ชันล้วน test ได้ครบ
- วันหยุดมีผลเฉพาะเมื่อตกช่วงวันที่ 27–29 ปีหนึ่งไม่กี่วัน

แลกกับ: มีวันหยุดพิเศษประกาศเพิ่ม ต้องแก้ไฟล์แล้ว deploy และต้องเติมรายการปีใหม่ปีละครั้ง

### ทำไมผูกงบกับเดือน M+1

- ตรงกับวิธีคิด: เงินที่ออกปลาย ก.ย. คือเงินใช้ของ ต.ค.
- งบที่ตั้งไว้แล้วใน tab `budgets` (key `YYYY-MM`) ใช้ต่อได้ทันที ไม่ต้อง migrate

## กติกา

### วันเงินออกของเดือน

```
payday(ปี, เดือน):
  d = min(29, วันสุดท้ายของเดือน)
  ขณะที่ d เป็นเสาร์ / อาทิตย์ / วันหยุดธนาคาร: d = d - 1 วัน
  คืน d
```

ตัวอย่างปี 2569:

| เดือน | วันที่ 29 | วันเงินออก |
|---|---|---|
| ก.พ. | ไม่มี — 28 เป็นเสาร์ | ศ. 27 ก.พ. |
| มี.ค. | อาทิตย์ | ศ. 27 มี.ค. |
| ก.ค. | พุธ (อาสาฬหบูชา), อังคาร 28 (เฉลิมฯ) | จ. 27 ก.ค. |
| ส.ค. | เสาร์ | ศ. 28 ส.ค. |
| ก.ย. | อังคาร | อ. 29 ก.ย. |
| ต.ค. | พฤหัส | พฤ. 29 ต.ค. |
| พ.ย. | อาทิตย์ | ศ. 27 พ.ย. |

### รอบของวันใดวันหนึ่ง

```
cycleFor(วัน):
  p = payday ของเดือนเดียวกับ วัน
  ถ้า วัน >= p: start = p,                      next = payday ของเดือนถัดไป
  มิฉะนั้น:     start = payday ของเดือนก่อน,    next = p
  end = next - 1 วัน
  budgetMonth = เดือนถัดจากเดือนของ start   (รูปแบบ YYYY-MM)
```

- วันเงินออกเองเป็นวันแรกของรอบใหม่
- รอบที่เริ่ม ธ.ค. มี `budgetMonth` เป็น ม.ค. ของปีถัดไป

### วันที่เหลือในรอบ

`daysLeft = next - วันนี้` (นับวันนี้ด้วย ไม่นับวันเงินออกครั้งถัดไป) — ค่าต่ำสุดคือ 1 ในวันสุดท้ายของรอบ ตัวเลขเดียวกันนี้ใช้ทั้ง "อีก N วันเงินออก" และตัวหารของ "ใช้ได้วันละ"

### เมื่อไม่มีรายการของปีนั้น

ถ้าปีของวันเงินออกครั้งถัดไป หรือปีของวันเริ่มรอบ ไม่มีในรายการ กติกายังทำงานด้วยเสาร์–อาทิตย์อย่างเดียว และหน้าหลักแสดงข้อความ: "ยังไม่มีรายการวันหยุดปี {พ.ศ.} — วันเงินออกอาจคลาดเคลื่อน"

เหตุผล: ความผิดพลาดชนิดนี้เงียบและดูน่าเชื่อ (รอบเลื่อนไป 1–2 วัน) จึงต้องบอกให้รู้

## หน้าหลัก

การ์ดขวาบน (เดิม "เดือนนี้"):

```
รอบนี้
฿12,340
29 ก.ย. – 28 ต.ค.
อีก 23 วันเงินออก
ของฉัน ฿11,200        ← เฉพาะเมื่อต่างจากยอดรวม (เหมือนเดิม)
```

- ยอด = ผลรวมรายจ่ายที่ `start <= date <= end`
- ช่วงวันที่และ "อีก N วัน" แสดงหลังข้อมูลโหลดเสร็จเท่านั้น หน้านี้ถูก prerender ตอน build — ข้อความที่ขึ้นกับ "วันนี้" จะไม่ตรงกับตอนเปิดจริงถ้า render ก่อน
- วันสุดท้ายของรอบ: "อีก 1 วันเงินออก"

การ์ดงบ:
- ป้าย "งบเดือนนี้" → "งบรอบนี้", "ตั้งงบเดือนนี้ →" → "ตั้งงบรอบนี้ →", "จ่ายจริงเดือนนี้" → "จ่ายจริงรอบนี้"
- ยอดใช้ = ส่วนของฉัน (myShare) ในรอบ — นิยามเดิม เปลี่ยนแค่ช่วงวันที่
- งบที่ใช้ = แถวใน `budgets` ที่ `month` = `budgetMonth` ของรอบ
- บันทึกงบ → เขียนด้วย `budgetMonth` ของรอบ
- บรรทัดใหม่ใต้ยอด: "ใช้ได้วันละ ฿X" โดย X = งบที่เหลือ ÷ `daysLeft` ปัดลงเป็นจำนวนเต็มบาท
  - แสดงเฉพาะเมื่อมีงบและยังไม่เกินงบ
  - งบเหลือ 0 หรือเกินงบ → ไม่แสดง (มี "เกิน ฿…" บอกอยู่แล้ว)

## หน้ารายการ

- ค่าเริ่มต้นของ "จากวันที่" = วันเริ่มรอบนี้ (เดิม: วันที่ 1) "ถึงวันที่" ว่างเหมือนเดิม
- แถวปุ่มใต้ช่องวันที่:
  - **"รอบก่อน"** — ตั้ง จาก/ถึง เป็นรอบก่อนหน้ารอบที่แสดงอยู่ (ดูจาก "จากวันที่"; ถ้าว่าง ใช้วันนี้) กดซ้ำถอยไปทีละรอบ
  - **"รอบนี้"** — กลับมารอบปัจจุบัน: จาก = วันเริ่มรอบ, ถึง = ว่าง
- แก้ช่องวันที่ด้วยมือได้เหมือนเดิม ปุ่มเป็นแค่ทางลัด
- ป้ายสรุปช่วง (`buildScopeLabel`) ไม่ต้องแก้ — แสดงตาม จาก/ถึง อยู่แล้ว

## ความเสี่ยงที่เหลือ

- วันหยุดพิเศษที่ประกาศกลางปีและตกช่วง 27–29 จะไม่ถูกนับจนกว่าจะเติมในโค้ด — รอบเพี้ยน 1–2 วันในเดือนนั้น
- ถ้าบริษัทเปลี่ยนวันจ่ายเงินเดือน ต้องแก้ค่าคงที่ในโค้ด
- ปี 2571 เป็นต้นไปต้องเติมรายการวันหยุดเมื่อ ธปท. ประกาศ — มีข้อความเตือนบนหน้าหลักเมื่อถึงเวลา

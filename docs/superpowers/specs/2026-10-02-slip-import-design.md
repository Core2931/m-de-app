# Slip Import — เพิ่มรายจ่ายจากสลิปหลายใบ

วันที่: 2026-10-02
สถานะ: design (อนุมัติแล้ว 2026-10-02)

## ปัญหา

Mark จดรายจ่ายตอนสิ้นวัน และต้องพิมพ์ ยอด / วันที่ / รายการ / หมวด ของแต่ละรายการเอง ทั้งที่หลายรายการมีสลิปอยู่ในมือถือแล้ว และร้านที่จ่ายก็ซ้ำเดิมเกือบทุกวัน

เป้าหมาย: สิ้นวันโยนสลิปหลายใบเข้าไป ได้ list ที่กรอกให้แล้ว ตรวจแล้วกดบันทึกทีเดียว

ปุ่ม "รายการประจำ" (merge แล้ว) ครอบคลุมรายการที่ไม่มีสลิป — feature นี้ครอบคลุมรายการที่มีสลิป

## ขอบเขต

**ทำ:**
- หน้า `/expenses/import`: เลือกรูปสลิปหลายใบ → อ่านในเบราว์เซอร์ → list ให้ตรวจและแก้ → บันทึกทั้งหมด
- จำร้าน: เก็บชื่อร้านจากสลิปลง Sheet แล้วใช้เติม รายการ + หมวด ให้สลิปใบถัดไปของร้านเดิม
- เตือนรายการที่อาจซ้ำ

**ไม่ทำ (YAGNI):**
- เก็บรูปสลิป — อ่านเสร็จทิ้ง รูปไม่ออกจากเครื่อง
- บันทึกอัตโนมัติโดยไม่ผ่านตา
- share จากแอปธนาคารเข้าเว็บ (PWA share target)
- parser เฉพาะธนาคารอื่นนอกจาก K+ และเป๋าตัง — ใช้กฎทั่วไป แล้วปรับเมื่อมีสลิปตัวอย่าง
- ตรวจสลิปปลอม / ยืนยันกับธนาคาร
- ใส่ข้อมูลหารเงิน (`remark`) ตอน import — แถวที่ต้องหารไปแก้ทีหลังในหน้าแก้ไข

## ข้อตกลงจากการ brainstorm

|---|---|
| ตัวอ่านสลิป | tesseract.js ในเบราว์เซอร์ — ฟรี ไม่มี API key รูปไม่ออกจากเครื่อง |
| จังหวะใช้งาน | สิ้นวัน หลายใบทีเดียว |
| การบันทึก | ต้องกดยืนยันเสมอ ทุกแถวแก้ได้ก่อนบันทึก |
| ที่เก็บชื่อร้าน | column H `payee` ใน tab `expenses` (Mark เลือกแล้ว เทียบกับ tab `payees` แยก) |
| key ของร้าน | ชื่อร้านจากสลิป จับคู่แบบใกล้เคียง — สลิป K+ สแกนจ่ายไม่มีเลขบัญชีผู้รับ |
| กันซ้ำ | เตือนเมื่อ วันที่ + ยอด ตรงกับรายการที่มีอยู่ — เลขอ้างอิง OCR อ่านไม่แม่น |
| ยอดของเป๋าตัง | ใช้ "จำนวนเงินที่ชำระ" (เงินที่ออกจริง) ไม่ใช่ราคาเต็ม |
| ความแม่น | ยอมรับว่าชื่อร้านสะกดเพี้ยนได้ ปรับจูนทีหลัง |

### ทำไมเก็บ `payee` เป็น column ใน `expenses`

เทียบกับ tab `payees` ที่เก็บคู่ ร้าน → รายการ/หมวด:
- ไม่มีข้อมูลสองที่ให้ desync — mapping คำนวณจากประวัติทุกครั้ง แบบเดียวกับ `buildFrequentItems` และ `buildKnownPeople`
- เรียนรู้เอง: บันทึกสลิปร้านใหม่ครั้งแรก ครั้งถัดไปก็เติมให้ ไม่มีหน้าตั้งค่า
- แก้ mapping = แก้รายการล่าสุดของร้านนั้น
- แถวเก่าและแถวที่กรอกมือมี `payee` ว่าง ไม่ต้อง migrate

แลกกับ: แก้ mapping ตรงๆ ไม่ได้ ต้องแก้ผ่านรายการ

## ผลทดลองที่ design นี้อิง

ทดลองกับสลิปจริง 4 ใบ (K+ สแกนจ่าย 3, เป๋าตัง 1) ผ่านหน้า `/slip-test` ใน Chrome:

| ข้อมูล | ผล |
|---|---|
| ยอดเงิน | 4/4 |
| วันที่ + เวลา | 4/4 |
| ชื่อร้าน | เจอ 4/4, สะกดเพี้ยน 3 ใบ |
| เลขอ้างอิง | อ่านไม่แม่น ไม่ใช้ |
| ความเร็ว | ~2 วิ/ใบ บน PC |
| โหลดตัวอ่าน | ~9 MB จาก cdn.jsdelivr.net ครั้งแรก — เน็ตบริษัทโหลดได้ |

ข้อค้นพบที่กำหนด design:
- สลิป K+ มีลายน้ำ ต้องแปลงขาวดำก่อนอ่าน ส่วนเป๋าตังอ่านภาพเดิมดีกว่า → อ่าน 2 รอบแล้วรวมผลทีละช่อง
- ข้อความที่ได้ในเบราว์เซอร์ต่างจากที่ได้ใน Node — กฎ parse ต้องทดสอบกับข้อความจากเบราว์เซอร์จริง

## Flow

1. หน้า "เพิ่ม" มีลิงก์ "เพิ่มจากสลิป" → `/expenses/import`
2. เลือกรูป (หลายใบได้) → ตัวอ่านโหลดครั้งแรก → อ่านทีละใบ มีข้อความ "กำลังอ่านใบที่ N จาก M"
3. แต่ละใบกลายเป็น 1 แถวใน list ทันทีที่อ่านเสร็จ
4. Mark ตรวจ แก้ หรือลบแถว
5. กด "บันทึกทั้งหมด (N)" → เขียนลง Sheet ทีละแถวตามลำดับ
6. แถวที่บันทึกสำเร็จหายจาก list ขึ้นข้อความ "✓ บันทึกแล้ว N รายการ"

เลือกรูปเพิ่มระหว่างที่มี list ค้างอยู่ → แถวใหม่ต่อท้าย ไม่ล้างของเดิม

## แถวใน list

| ช่อง | ค่าเริ่มต้น | แก้ได้ |
|---|---|---|
| วันที่ | จากสลิป; อ่านไม่ได้ → วันนี้ + ป้าย "ใช้วันนี้" | ได้ |
| ยอด | จากสลิป; อ่านไม่ได้ → ว่าง | ได้ |
| รายการ | จากร้านที่จำได้; ไม่รู้จัก → ว่าง | ได้ |
| หมวด | จากร้านที่จำได้; ไม่รู้จัก → `DEFAULT_CATEGORY` | ได้ |
| ร้าน | ชื่อที่อ่านได้ แสดงเป็นข้อความรอง | ไม่ได้ |

`remark` ว่างเสมอ

ป้ายบนแถว:
- **"อาจซ้ำ"** — มีรายการใน store ที่ `date` และ `amount` ตรงกัน หรือมีแถวอื่นใน list เดียวกันที่ตรงกัน ไม่บล็อกการบันทึก
- **"ใช้วันนี้"** — อ่านวันที่ไม่ได้

ปุ่ม "บันทึกทั้งหมด" กดไม่ได้ถ้ามีแถวที่ ยอด ≤ 0 / ว่าง หรือ รายการว่าง — ขึ้นข้อความ "แก้ N แถวก่อนบันทึก" และแถวที่ติดมีขอบเตือน

## การจำร้าน

### เก็บ

- `Expense` เพิ่ม field `payee?: string`
- บันทึกจาก import → `payee` = ชื่อร้านที่อ่านได้ (trim, ยาวไม่เกิน 100 ตัวอักษร)
- บันทึกจากฟอร์มปกติ → ไม่ส่ง `payee`
- หน้าแก้ไขรายการไม่แสดงและไม่แตะ `payee`

### จับคู่ (`lib/payees.ts`)

```
suggestFromPayee(payee: string, expenses: Expense[]): { item, category } | null
```

1. normalize ทั้งสองฝั่ง: ตัดช่องว่าง เครื่องหมาย ตัวเลข สระบน/ล่างและวรรณยุกต์ออก, lowercase
   - เหตุผล: ข้อผิดพลาดของ OCR ที่พบคือสระ/วรรณยุกต์หาย ("คาเฟ่" → "คาเฟ") และตัวเลขเพี้ยน ("P3821" → "23821")
2. ชื่อหลัง normalize สั้นกว่า 3 ตัวอักษร → ไม่จับคู่
3. หา `payee` ในประวัติที่ edit distance ≤ 20% ของความยาวชื่อที่ยาวกว่าในคู่นั้น (ปัดลง, ขั้นต่ำ 1)
4. ถ้าระยะใกล้สุดเสมอกันระหว่างสองร้านที่ต่างกัน → ไม่จับคู่ (ไม่เดา)
5. คืน `item` + `category` ของรายการล่าสุดของร้านนั้น

ใช้ `editDistance` ที่มีอยู่ใน `lib/people.ts` — ย้ายออกมาเป็น export ใน `lib/utils.ts` แล้วให้ทั้งสองไฟล์ใช้ร่วมกัน

ร้านที่ OCR อ่านเพี้ยนหนัก (เช่น "ทองใบshop" → "ทองใบรก๐๐") อาจจับคู่ไม่ได้ในบางครั้ง ผลคือต้องพิมพ์รายการเอง — ยอมรับได้ และปรับเกณฑ์ทีหลังได้โดยไม่กระทบข้อมูล

## การอ่านสลิป

ใช้โค้ดจาก branch ทดลอง:

- `lib/slipOcr.ts` — โหลด tesseract.js (tha+eng) แบบ dynamic import, อ่าน 2 รอบ (ขาวดำ threshold 120 + ขยาย 2 เท่า แล้วตามด้วยภาพเดิม), คืนผลที่รวมแล้ว
- `lib/slipParse.ts` — ข้อความ OCR → `{ amount, date, time, payee }`; `mergeSlipReads` รวมสองรอบทีละช่อง รอบขาวดำมาก่อน

ไฟล์ตัวอ่านโหลดจาก CDN ตามค่าเริ่มต้นของ tesseract.js ไม่ฝากใน repo

## Sheet

tab `expenses` เพิ่ม column H:

```
id | date | item | amount | remark | createdAt | category | payee
```

- อ่าน: range เป็น `A2:H`, แถวที่ไม่มี column H → `payee` เป็น `undefined`
- append: เขียน 8 column
- update: เขียนแค่ `A:G` เหมือนเดิม → `payee` ของแถวนั้นคงอยู่เมื่อแก้รายการ
- header `payee` ใน H1 ไม่บังคับ — append ทำงานได้โดยไม่มี header แต่แนะนำให้เพิ่มเพื่อให้ Sheet อ่านง่าย (เพิ่มใน README)

## API

`POST /api/expenses` รับ `payee` เพิ่ม (optional) — `validateExpenseInput`:
- ไม่ใช่ string หรือว่างหลัง trim → ไม่มี `payee`
- ยาวเกิน 100 → ตัดเหลือ 100

ไม่มี endpoint ใหม่ การบันทึกหลายแถวเรียก `add()` ของ store ทีละแถวตามลำดับ (ไม่ยิงพร้อมกัน — append พร้อมกันบน Sheets เสี่ยงเขียนทับแถว)

## Error handling

| กรณี | พฤติกรรม |
|---|---|
| โหลดตัวอ่านไม่สำเร็จ | ข้อความ "โหลดตัวอ่านไม่สำเร็จ — เลือกรูปอีกครั้งเพื่อลองใหม่" ไม่มีแถวถูกสร้าง การเลือกรูปใหม่คือการลองใหม่ |
| อ่านรูปใดรูปหนึ่งไม่ได้ (ไฟล์เสีย / ไม่ใช่รูป) | แถวนั้นขึ้นเป็นแถวว่างพร้อมชื่อไฟล์และข้อความ "อ่านไม่ได้" กรอกเองหรือลบได้ ใบอื่นอ่านต่อ |
| อ่านยอดไม่ได้ | ช่องยอดว่าง แถวติดเตือน บล็อกปุ่มบันทึก |
| บันทึกบางแถวไม่สำเร็จ | หยุดที่แถวนั้น แถวที่สำเร็จแล้วหายจาก list แถวที่เหลือค้างไว้พร้อมข้อความ กดบันทึกซ้ำได้ ก่อนเปิดให้กดซ้ำ แอปโหลดรายการจาก Sheet ใหม่ — ถ้าแถวที่ล้มเขียนลง Sheet ไปแล้วแต่คำตอบไม่กลับมา แถวนั้นจะขึ้น "อาจซ้ำ" |
| ระหว่างกำลังบันทึก | ทุกแถวถูกล็อก แก้หรือลบไม่ได้จนกว่าจะบันทึกเสร็จหรือล้ม |
| วันที่บนสลิปไม่น่าเป็นไปได้ (อนาคต, เก่ากว่า 1 ปี, ไม่มีในปฏิทิน) | ถือว่าอ่านวันที่ไม่ได้ → ใช้วันนี้ + ป้าย "ใช้วันนี้" |
| หาชื่อร้านไม่เจอในตำแหน่งที่คาด (สลิปโอนเงิน, ชื่อร้านอังกฤษล้วน) | ไม่มีชื่อร้าน ไม่เติมรายการ — ไม่หยิบข้อความอื่นบนสลิปมาแทน |
| ออกจากหน้าทั้งที่มีแถวค้าง | แถวหาย ไม่มีการเก็บ draft |

## ความเสี่ยงที่เหลือ

- ความเร็วบนมือถือยังไม่มีตัวเลขที่วัดไว้ — Mark ลองหน้าทดลองบน preview แล้วบอกว่ารับได้
